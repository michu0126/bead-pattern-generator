# 识图精度优化（v1.9.0，2026-10-11）

v1.9.0 在 v1.8.0 基础上优化识图精度，保持 MARD 221 色数据、抠图引擎和配置的 Image2 调用模型。

## 本地：保留没有被任何格子表示的小特征

继续先按原像素 HEX 精确匹配，未命中时在完整 MARD 色卡中使用 CIEDE2000 选色，然后按实际覆盖面积和 alpha 投票，不插值混合 RGB。

补充一步保守的连通区域检查：眼睛等小色块跨在格子交界处时，可能在每格中都输给底色而完全消失。满足以下条件且完全没有输出格代表的区域，最多补回一格：

- 98% 不透明核心像素的色号不超过 32 种。这只是低色复杂度门槛，不是照片分类器，也不限制颜色匹配候选。
- 核心 alpha 至少 224；区域总面积为单格源面积的 0.25～3 倍，至少 4 个源像素；横纵跨度均不超过 3 格。
- 周围是连续不透明内容，至少 65% 周边像素与该区域的 ΔE00 不小于 20。
- 候选格至少包含该区域 8% 的单格源面积；已有代表则不重复补，不覆盖空格，也不删除其他色号唯一的局部代表。

因此不是全局锐化、中心加权、限制豆色数量或随意清灰。一个细节不能在一格中还原全部形状，此处选择保留其存在性。过长细线、过小区域、低对比细节仍可能丢失；原图自带的 JPEG/WebP 抗锯齿灰色仍按真实输入匹配，不自动推断成黑白。

连通区域只为合格候选分配包围盒，避免大量碎噪点创建数百万个 Python 对象。

## Image2：解析图纸时不再二次错误取色

旧浏览器实现假设格子铺满图片，用每格 16 个点取色，再用 RGB 欧氏距离匹配，最后删除边缘连通白色。边距、字码、网格线都可能导致错色；原图中的白色也可能被删掉。

新流程在服务器检测重复网格线，识别外边距，并避开格线和格子中央字码，从填色区域选择实际存在的代表像素，再使用与本地一致的 HEX/CIEDE2000 匹配。它不是 OCR，不以模型印出的字码作为颜色真值。检测到行列数与板子不符时明确报错；未能可靠定位完整网格时给出警告，不宣称精确解析。

不投影原图 alpha 到 AI 重新生成的构图，防止位置变化误删主体。不透明原图不再自动删外部白色。仅当原图已有透明区域、AI 图纸却没有透明空格，而且网格和字码证据都存在时，才将“与板边四连通、近白、无字”的格子判空，并显示核对提示。带字白格、封闭白区保留；缺少证据则不猜。小于 8 像素的格子会提示字码遮色风险，超过 4096 像素的输出拒绝解析以保护 NAS 资源。

后端材料清单、浏览器编辑、导出都使用同一份色号网格；删除额外的视觉模型估数请求。材料数是**最终网格的准确计数**，不代表模型生成内容与原图 100% 一致。Image2 生成仍会产生配置供应商的费用，解析和计数本身不额外调用模型。

## 验证与实际边界

新增合成测试涵盖跨格双眼、已有黑框、小噪点、透明边缘、所有色号逐像素保持、四种板型的带字网格、边距、压缩、白色主体、错误行列数，以及编辑后材料数同步。浏览器回归使用模拟 API，未调用付费模型，不将它当作真实 Image2 识图质量评测。

2026-10-11 本机验证：324 项 Python 测试、3 项前端逻辑测试全部通过；浏览器的上传、4 种板型、抠图采用/弃用、双生成、编辑/清除/撤销、材料与下载、重复保存 API 设置及移动端布局回归通过。依赖中有一条 Starlette/AnyIO 弃用警告，不影响测试结果。

用户的 1080×1080 酷洛米 WebP：52 板仅修改 2 格，补回鼻子轮廓/小嘴附近黑色细节；72、78、104 板逐格结果保持不变。52 板本机一次测量约 0.78→1.22 秒，占格数均为 1209、色号仍为 10 种。精度补偿有运算成本，不声称加速。
