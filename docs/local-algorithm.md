# 本地生成算法优化（v1.8.0）

v1.8.0 调整 `app/pattern.py` 的本地路径。Image2、抠图引擎、MARD 色卡数据及 HTTP 响应结构不变，本地生成不调用模型、不消耗 Token。算法、接口与既有功能共 288 项测试通过。

## 发现的问题与处理

| 原有问题 | 本次处理 |
| --- | --- |
| 为铺满方板，居中裁掉长图两端 | 使用等比完整适配，缺少的区域留空，不拉伸、不裁切 |
| 小板放大后将取景框限制在原图边界，可能再次裁掉主体 | 允许取景框超出原图，超出部分透明；52 钉板在留白足够多时聚焦主体，预留两格边距 |
| 透明抠图中的白色仍被按背景规则删除 | 存在透明度时，以已有透明通道为准，不再清理白色 |
| 明亮米白、浅粉被过宽的“近白”阈值吞掉 | 仅对完全不透明图片使用更窄的近白背景规则；纯白/纯色图片没有可分离背景证据时保留 |
| Python 队列逐像素遍历大面积背景 | 用四连通区域标记处理白色区域，减少 Python 对象分配 |
| 隐藏 RGB 也计算色卡距离 | 只匹配可见像素，重复 HEX 只计算一次 |
| 大批量色差矩阵占用较多内存 | 每批最多 512 个颜色，仍遍历完整 221 色，不用近似候选过滤 |
| 面积平票时距离被截断，可能选到较远色块 | 使用未截断的中心距离决胜 |

## 当前流程

1. 校正 EXIF 方向、读取 RGBA。最长边超过 4096 时仍执行原有最近邻分析限幅，不插值混色。
2. 处理可见性：已有透明通道优先；完全不透明图仅识别近白背景，保留被主体包围的白色。背景规则是启发式，不是语义识别。
3. 将可见原像素的 24 位 HEX 与项目中的 MARD 数字色卡精确匹配；未命中时使用完整色卡的 CIEDE2000 距离选择相近色。
4. 按比例把图片放入板子。对每格计算源像素与该格的实际重叠面积，用面积乘透明度给色号投票。有效覆盖率低于 8% 留空，其余选票数最多的色号；完全平票时选择更靠近格子中心的色号。
5. 图纸、可编辑网格和材料数量均来自同一份色号网格，保证数量一致。

## 不应承诺的能力

- 一格只能放一种颜色，缩到 52 × 52 不可能保留原图的所有细节。
- 不擅自合并相近 HEX，不做 RGB 均值缩放，也不为减少豆色而覆盖真实颜色。
- 原图本身的抗锯齿、JPEG/WebP 压缩杂色仍属于输入颜色，严格匹配不会自动推断并恢复它们的“原本纯色”。
- 不透明图片的白背景和白色主体有时无法仅凭颜色区分；要明确保留白色主体，应采用有透明通道的抠图结果。
- 4096 分析限幅仍会丢失超大原图的部分细节；本轮没有取消 NAS 的资源保护。

## 可复现验证

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
python scripts/benchmark_pattern.py --baseline-ref 1d811c20b6eb493475bebaa74b4a40a7a5c02310 --output-dir /tmp/bead-comparison
```

基准对旧版和优化版各启动独立进程，输出耗时、进程峰值内存、使用色号和占格数。数据为合成图，不调用任何 API；也可通过 `--fixture 图片路径` 检查实际图片。生成的 PNG 仅写入指定输出目录，原图不变。单次基准不等同于所有图片或 NAS 的实际性能。

连通区域实现参考：[SciPy label](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.label.html) 与 [binary_dilation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.binary_dilation.html)。

## 2026-09-06 本机单次基准

| 52 钉样例 | 旧版耗时 → 优化后 | 进程峰值内存（MiB）旧 → 新 | 结果 |
| --- | --- | --- | --- |
| 900 × 300 三色色带 | 0.555 → 0.269 秒 | 43.5 → 73.1 | 旧版只剩中间绿色；新版保留红、绿、蓝完整画面 |
| 600 × 600 透明白色主体 | 1.412 → 0.404 秒 | 67.5 → 74.7 | 旧版白色主体被删除；新版保留白色和黑色 |
| 256 × 256 隐藏随机 RGB | 9.979 → 0.335 秒 | 265.6 → 61.5 | 仅一个可见红色色号，跳过不可见噪声颜色的距离计算 |
| 1200 × 1200 白底小花 | 5.356 → 0.690 秒 | 176.1 → 89.3 | 两版均为相同三个色号；新版聚焦使用更多有效钉位 |
| 用户提供的 1080 × 1080 酷洛米 WebP | 3.485 → 0.951 秒 | 303.4 → 118.0 | 形状总体接近，色号从 11 种变为 10 种；原有抗锯齿颜色仍按色卡匹配 |

基准使用 Windows / Python 3.12，计时只覆盖色号网格生成，不包含 PNG 绘制和进程启动。峰值内存包含库导入等固定开销，因此小图不一定减少内存。两版的主体放大比例不同，不应把占格数变化误认为颜色识别精度得分。不是对所有图片、照片或 NAS 的速度保证。
